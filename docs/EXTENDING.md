# คู่มือต่อยอด (Recipes)

ทุกสูตรด้านล่างทำได้ **3 ทาง** เลือกตามถนัด: (ก) หน้า "ตัวแก้ไข" ในแอป (ข) วาง JSON ที่หน้า "ข้อมูล → นำเข้า/รวมข้อมูล" (ค) แก้ `skill-lab/src/01-defaults.js` แล้ว `python3 build.py`
> ข้อมูลที่แก้ในแอปเก็บใน localStorage ของเบราว์เซอร์ — ถ้าจะให้เป็น "ค่าเริ่มต้นถาวร" ให้ส่งออก JSON แล้วย้ายลง `01-defaults.js` (หรือกด "คืนค่าเริ่มต้น" เมื่อแก้ defaults)

## 1. เพิ่มสกิล

**ในแอป:** ตัวแก้ไข → แท็บ "สกิล" → กรองคลาส → `＋ สกิลใหม่` → กรอกฟอร์ม (ข้อมูลหลัก → การเชื่อมต่อ → อาวุธ → การใช้งาน → ดาเมจ → ผล) · มี "ข้อควรตรวจ" ด้านบนและตารางค่าทุกเลเวลด้านล่างให้เช็คทันที · `ทำสำเนา` เพื่อเริ่มจากสกิลคล้ายกัน

**ด้วย JSON (รวมเข้า):** ตัวอย่างเพิ่มสายกริชให้โจร (คลาส `thief` มีอยู่แล้วเป็นโครงเปล่า)

```json
{
  "branches": [ { "id": "th_blade", "class": "thief", "name": "สายกริช" } ],
  "skills": [
    { "id": "thDagger", "class": "thief", "name": "ชำนาญกริช", "type": "passive", "branch": "th_blade", "tier": 1, "jobLvReq": 2, "maxLevel": 5,
      "weaponReq": { "include": ["dagger"] },
      "effects": [ { "stat": "atk", "mode": "flat", "value": { "base": 4, "step": 4 } } ] },
    { "id": "thBackstab", "class": "thief", "name": "แทงข้างหลัง", "type": "active", "branch": "th_blade", "tier": 2, "jobLvReq": 10, "maxLevel": 5,
      "requires": [ { "id": "thDagger", "lv": 3 } ], "weaponReq": { "include": ["dagger"] },
      "usage": { "sp": { "base": 8, "step": 1 }, "cooldown": 4 },
      "damage": { "kind": "physical", "terms": [ { "stat": "atk", "mult": { "base": 1.4, "step": 0.25 } } ] } }
  ]
}
```
จากนั้นเปลี่ยนคลาสทดสอบเป็นโจร → ต้นไม้สกิลจะแสดงสายใหม่เอง · ตรวจที่หน้า "ข้อมูล" ว่าไม่มี error

**เช็กลิสต์ตอนออกแบบสกิลใหม่**
1. กำหนด `tier` (แถว) และ `jobLvReq` ให้เรียงขึ้นตามลำดับ (ถ้าเงื่อนไขปลดล็อกหลังตัวสกิล validator เตือน)
2. ใส่ `duration` ถ้ามี `effects` ในสกิล active/buff ไม่งั้นไม่เกิดสถานะ
3. ถ้าเป็นสกิลดาเมจ ดู "ดาเมจ/SP" และ "DPS*" ในตารางหน้าจำลองเทียบกับสกิลเดิม แล้วรัน "เทียบบิลด์" (benchmark)
4. จำนวนเลเวลรวมของคลาสควรมากกว่าแต้มที่ได้ประมาณ 1.5–2.5 เท่า (นักดาบตอนนี้ซื้อได้ 63%, ชาวบ้าน 41%) เพื่อให้ต้องเลือกบิลด์ — ดูแถว "info" ในหน้า "ข้อมูล"

## 2. ปรับ "การเชื่อมต่อสกิล" (prerequisite)

การเชื่อมต่อ = `requires:[{id, lv}]` ของ **สกิลปลายทาง** (ต้องมีครบทุกข้อ) แก้ได้จากทั้งสองฝั่งในตัวแก้ไข:

| ต้องการ | ทำที่ |
|---|---|
| ให้สกิล A ต้องมี B Lv3 ก่อน | เปิด A → "การเชื่อมต่อสกิล" → `＋ เพิ่มเงื่อนไข` เลือก B → ตั้ง Lv |
| ให้ A เป็นเงื่อนไขของ C | เปิด A → `＋ ให้สกิลนี้เป็นเงื่อนไขของ…` เลือก C |
| ถอดการเชื่อม | `✕` ข้างเงื่อนไข หรือ `ถอดการเชื่อม` ในรายการ "ปลดล็อกต่อ" |
| ย้ายสกิลไปแถว/คอลัมน์อื่น | เปลี่ยน `Tier` / `สาย` ในข้อมูลหลัก — กราฟจัดวางใหม่เอง |

ตัวเลือกใน dropdown ตัดสกิลที่จะทำให้เกิดวงกลม (เป็นลูกหลาน/บรรพบุรุษ) ออกให้แล้ว · validator ยังจับ cycle ที่เกิดจากการแก้ JSON ตรง ๆ · ลบสกิลที่เป็นเงื่อนไขของสกิลอื่น = ระบบถอดการเชื่อมให้อัตโนมัติ · เปลี่ยน `id` = แก้อ้างอิง `requires` ในทุกสกิล, บิลด์ตัวอย่าง, สกิลที่ลง, และลำดับอัตโนมัติให้ครบ

## 3. เพิ่มคลาส / สาย

ตัวแก้ไข → "คลาส & สาย" → `＋ คลาสใหม่` (ตั้งคลาสแม่ = สายอาชีพที่ต้องผ่านก่อน, `jobLvCap`, `pointsPerJobLv`) → `＋ สายใหม่` ในคลาสนั้น → เพิ่มสกิลโดยเลือกคลาส/สายเดียวกัน
- คลาสลูกจะได้แต้มของคลาสแม่เต็ม (จบแล้ว) และเห็นสกิลคลาสแม่ในต้นไม้
- ตั้ง `parent` ให้คลาสอาชีพ 2 (เช่น อัศวิน ← นักดาบ) ได้เลย: โซ่ `novice → swordman → knight`
- ลบคลาสได้เมื่อไม่มีสกิลเหลือในคลาสนั้น
- ถ้าเพิ่มด้วย JSON: ใส่ใน `classes` (`{id,name,parent,jobLvCap,pointsPerJobLv,desc}`) · ถ้าต้องการบิลด์/พรีเซ็ตของคลาสใหม่ เพิ่มใน `builds`/`presets`

## 4. เพิ่มสเตตัสใหม่

1. เพิ่มใน `statDefs` (`id`, `name`, `group`, `kind: num|frac|pct`)
2. ใส่ค่าในชีตของ preset (ไม่ใส่ = 0)
3. ใช้ใน `effects[].stat` หรือ `damage.terms[].stat` ได้ทันที
4. ถ้าสเตตัสนั้นต้อง "มีผลต่อการต่อสู้" (เช่น `lifesteal`) ต้องเพิ่มตรรกะใน `04-stats.js`/`05-sim.js` (ดูข้อ 7)
5. ถ้าจะให้มอนสเตอร์ได้ผลจาก `appliesTo:'target'` ของสเตตัสนั้น เพิ่มคีย์ใน `S` ของ `calc.monster`

## 5. เพิ่มอาวุธ

เพิ่มใน `weapons` (`id, name, slotType, damageType, weaponClass`) → ใช้ใน `weaponReq.include/exclude` และ dropdown อาวุธทันที (ตัวเลข ATK/ASPD ของอาวุธใส่ในชีต preset)

## 6. เพิ่มมอนสเตอร์ทดสอบ / บิลด์ / พรีเซ็ต

เพิ่มใน `monsters` / `builds` / `presets` (ดู `DATA_SCHEMA.md`) · บิลด์ต้องเรียนได้จริงตามกฎ — รัน `npm test` เพื่อให้ `tests/test-core.js` ตรวจว่าทุกบิลด์ลงสกิลได้ครบและงบแต้มไม่ติดลบ

## 7. เพิ่มกลไกใหม่ในตัวจำลอง

**จุดต่อ (hook points)** ใน `05-sim.js`:

| อยากทำ | แก้ที่ |
|---|---|
| ผลพิเศษตอนใช้สกิล (stun, knockback, ลดคูลดาวน์, ขโมย HP) | ใน `doCast(skill)` หลังส่วนดาเมจ/ฟื้นฟู — อ่านจาก `skill.hooks.xxx` |
| ผลตอนโดนตี/ตีโดน (reflect, lifesteal, thorns) | ใน `applyHit` (ฝั่งผู้เล่น) และบล็อก "มอนสเตอร์สวนกลับ" ใน `tick()` |
| สถานะต่อเนื่อง (DoT, regen เฉพาะสถานะ) | เพิ่มฟิลด์ใน entry ของ `pst/mst` แล้วประมวลผลใน `tick()` ถัดจากบล็อก toggle |
| ชนิดสกิลใหม่ (เช่น `channel`, `aura`) | เพิ่มใน `ui.TYPES` (06) + `rules.isCastable` (03) + แยกพฤติกรรมใน `doCast/tick` + `normalizeSkill` ถ้ามีฟิลด์ใหม่ |
| ระบบยา/ไอเท็ม | เพิ่ม "ช่องใช้ยา" เป็นกฎ rotation ชนิดพิเศษ (เช่น `rule.item`) แล้วจัดการใน `choose()` |
| หลายเป้าหมาย | เปลี่ยน `mhp/M/mst` เป็นอาเรย์ของเป้า แล้วให้ `damage.aoe` วนเป้า — ตอนนี้ใช้ `opts.aoeTargets` คูณแบบง่าย |
| สูตรดาเมจ/เกราะ | `calc.components` และ `calc.roll` ใน `04-stats.js` (ที่เดียว ใช้ทั้งตารางคาดการณ์และตัวจำลอง) |

สูตรการ "ตรวจเงื่อนไข" (`why()` ใน sim และ `rules.canLearn`) แยกกันโดยตั้งใจ: ฝั่งแรกคือเงื่อนไขตอนต่อสู้ ฝั่งหลังคือเงื่อนไขตอนลงแต้ม

เพิ่ม/แก้ฟิลด์ของสกิล → แก้ `normalizeSkill` (default) + `validate` (ตรวจ) + `10-ui-skillform.js` (ช่องกรอก) ตามลำดับ

## 8. เพิ่มหน้า (แท็บ) UI ใหม่

1. สร้าง `src/NN-ui-xxx.js` ที่ลงทะเบียน `SL.ui.pages.xxx = { mount(root), update(reason), onShow?, onHide? }`
2. เพิ่มชื่อใน `NAMES` ที่ `99-main.js` และลิงก์ `<a href="#xxx" data-tab="xxx">` ใน `shell.html`
3. ใช้ ASCII ล้วนสำหรับชื่อ hash

## 9. เชื่อม Status Lab

ตอนนี้: คัดลอกค่าสเตตัสจาก Status Lab (ตาราง Derived Stats) → วางเป็น JSON ที่ "จำลอง → สเตตัสของตัวละคร (ชีต) → นำเข้า" เช่น `{"atk":56,"aspd":105,"hit":90,"maxHp":1904,"maxSp":384,"def":14.8}` (รหัสสเตตัสต้องตรงกับ `statDefs`)
งานต่อที่แนะนำ: เพิ่มปุ่ม "คัดลอกเป็น JSON สำหรับ Skill Lab" ใน Status Lab (map `computeDerived` → คีย์ `atk, matk, hit, flee, aspd, physCrit, magicCrit, mdefIgnore, critDmg(=critDamageBonus), def, mdef, maxHp(=hp), maxSp(=sp), hpRegen, blockChance, defPen`)

## 10. เพิ่มโมดูลโค้ด

สร้าง `src/NN-ชื่อ.js` (เลขกำหนดลำดับโหลด ห่อด้วย IIFE และผูกกับ `SL.xxx`) แล้ว `python3 build.py` — ไม่ต้องแก้ build script · ห้ามให้โมดูลที่ `< 06` แตะ DOM

## 11. ไอเดียงานต่อ (roadmap)

- สกิลโจร/นักธนู/จอมเวท โครงเดียวกับนักดาบ (ดู `docs/design-notes/21-swordman-skill-design.md` เป็นแม่แบบ: จัดสาย 3 สาย, tier 4 ชั้นที่ Job Lv 2/10/25/40, ชนิดสกิลครบ 5 แบบ)
- ระบบยา/ฮีลเองสำหรับ benchmark (ตอนนี้บิลด์ที่ HP ไหลตายเมื่อมอนสเตอร์สวนกลับ)
- หลายเป้าหมาย + threat/taunt ให้บิลด์โล่มีบทบาทชัด
- สถานะ stun/knockback จาก `hooks`
- คลาสอาชีพ 2 ที่ Job Lv.50 (ตามที่วางไว้ในแผน)
- ใช้สกิลของ Skill Lab ใน Status Lab (แผน 3 ระยะ: ระยะ 1 ย้ายสกิลเป็น passive ที่มีผลต่อสเตตัส → ระยะ 2 ใส่สกิลแอคทีฟ → ระยะ 3 ปรับ UI)
